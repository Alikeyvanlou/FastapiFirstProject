توی روش عادی، همه‌ی مراحل ساخت image توی یه stage انجام می‌شه؛ یعنی کامپایلر و ابزارهای build (مثل gcc) هم توی image نهایی باقی می‌مونن، در حالی که بعد از نصب پکیج‌ها دیگه بهشون نیازی نیست. این باعث می‌شه حجم image غیرضروری بالا بره و سطح حمله (attack surface) هم بیشتر بشه.

توی multi-stage، فرآیند به دو مرحله تقسیم می‌شه. مرحله‌ی اول (builder) از یه image کامل استفاده می‌کنه که کامپایلر داره و پکیج‌ها رو نصب می‌کنه. مرحله‌ی دوم از یه image سبک‌تر (slim) شروع می‌شه و فقط فایل‌های لازم برای اجرا (نه ابزارهای build) از مرحله‌ی اول کپی می‌شن. در نتیجه image نهایی هم سبک‌تره و هم امن‌تر، چون فقط چیزی که واقعاً برای اجرای برنامه لازمه توش هست.
